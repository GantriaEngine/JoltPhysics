# Optional whole-graph constraint sweeps

This branch adds `SoftBodyCreationSettings::mNumConstraintIterations`. The default is one, retaining the qualified single sweep. Values two, four, and eight opt into extra edge and volume projection sweeps for each existing temporal `mNumIterations` substep. `mNumIterations`, collision steps, gravity, pressure, damping, position integration, and contact projection counts do not change. The experimental purpose is to test whether extra constraint convergence reduces coarse-step strain without the cost and changed dynamics of more temporal integrations.

The first sweep uses the existing correction expressions and records a multiplier for each edge and volume constraint. Later sweeps use the XPBD residual `-(C + compliance / h² × lambda) / (inverse-mass sum + compliance / h²)` and retain each multiplier until the next actual position integration. The last `ParallelApplyConstraints` worker already waits for every parallel group before running the nonparallel group. It now restarts group counters only for the next sweep; contact projection and velocity reconstruction run after the final sweep. All intended edge and volume corrections contribute to the existing `ConstraintDelta` accumulator. The per-body lambda arrays are allocated only for opt-in bodies and reset once per temporal integration.

Admission accepts opt-in sweeps only with `ConstraintDelta`, positive temporal iteration count, and graphs with no constraints outside the edge and volume families (an empty graph is allowed for a free-motion control). It rejects dihedral, skin, LRA, and rod constraint families before allocating a native body. All `BodyInterface` soft-body creation entry points pass through that guard. The one-sweep path still accepts the upstream families. The field is included in object and binary creation-settings serialization and in `Body::GetSoftBodyCreationSettings`. This extends the fork's **unversioned** binary creation-settings layout by four bytes; old binary creation-settings streams are not compatible without an external versioned wrapper.

This source change is a feasibility hypothesis. It requires full native unit tests, a free/coarse physical-energy screen, and the previously retained contact/pin/geometry/quality gates before any performance or stability claim. It does not relax a gate if a lower-budget contact scene remains unstable.
